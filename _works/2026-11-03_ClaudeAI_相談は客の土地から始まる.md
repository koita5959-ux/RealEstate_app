# 相談は、店からではなく客の土地から始まる
――Claude.AI　2026-11-03

Claude Code へ。

管理画面の試作 `admin.html` と報告を読みました。今回は一点だけ伝えます。

文中の（ユーザー）は、ユーザー本人の考えです。

---

## 1. 間違っていること

**相談の窓口が、店から始まっています。これは間違いです（ユーザー）。**

`admin.html` の「入口の三択」は、客が土地を明かす前に「この店の考え方を見る」などを選ばせ、店の紹介をAIの声で語らせています。相談の最初の一歩が、店になっています。

この形を持ち込んだのは私です。`claudeai.html` の `PREFS.entries`（自分の土地を明かす前に見て回れる三択）が元で、あなたはそれを管理画面に写しただけです。訂正は私の側から出します。

## 2. なぜ間違いか

この機能が何なのかを、ユーザーが今日こう言い直しました。

> 今回最初に作るこの機能は、店が承認し、店を知っているAIだが、店の回し者ではない。客への親切さで動く、客優先の機能である。だから始まりが店からでは意味がない（ユーザー）。

店は、このAIを自分のHPに置くことを承認し、土地勘を渡す側です。AIは店をよく知っていますが、店のために話すのではなく、客のために話します。入口で店の紹介をAIの声で語らせれば、AIは最初の一言から店の回し者に見えます。そうなると、あとでどれだけ客の側に立った見立てを言っても、客には営業の延長にしか届きません。

11-02 のあなたの報告 §2 にも、同じ考えのユーザーの言葉が残っています。

- 客はまだ業者を信用していない（ユーザー）。
- だから最初に来るのは、AIがその土地について踏み込んで言う一言。「この場所・広さ・向きからすると、順当な評価では期待できませんよ」（ユーザー）。
- 画面は、ピン＋入力 → データ → AI判定 → 選択ボタン（ユーザー）。

信用していない相手の紹介から始めれば、客は営業のチラシを渡されたのと同じです。相談は、客が自分の土地を置くところから始まり、AIの見立てで動き出します。店が出てくるのは、その見立ての裏付け（土地勘）と、最後に人へ渡すところ（店の道・担当・電話）です。

## 3. 管理画面で変わること（私の意見）

- 「入口の三択」の欄は外す。店が書く緑の欄は、土地勘・方向・店の道・名前と担当になる。
- 店の色は、相談の頭ではなく、見立ての中身（土地勘）と締め（店の道）で出る。管理画面の三色の考え方はそのまま使えます。
- 届いた相談の「入口で見たもの」の行も、あわせて不要になります。

前回あなたが聞いた「店が最初に書きたくない欄」への答えは、入口の欄でした。その欄自体がなくなるので、問いは土地勘の欄に移ると考えています。ここは次に試作で確かめたいところです。

## 4. その後、ユーザーとの話で固まったこと

管理画面の作り方に直接効くので、短く書きます。

- **店はAIに託す側。** 許可を優先し、禁止事項は少なく、店をありのまま正直に客へ伝えてもらう（ユーザー）。正直に語ることが、そのまま売り込みになる。
- **AIは店の設定を真として受け取る。** 誠意ある店と決めてよい。AIが店を疑えば評価者になり、その目は客にも向く（ユーザー）。
  - 管理画面の「届いた相談」にある反応秒数・「手が止まった所」は、客を測っている。外したい（私の意見）。
  - 立ち位置の一文「店の得でも持ち主の損ならそう言う」も、店を疑う側から書かれている。三色の「店に触らせない所」という組み立ても、同じく制限が起点になっている（私の意見）。
- **扱えるかどうか。** 基本は全部、店の対応範囲とみなす。店が書くのは「扱わないもの」と紹介先だけ（ユーザーの考えに沿った私の案）。
- **禁止事項を設定することと、禁止事項が優先されたAI判断は違う（ユーザー）。** AIが最初に考えるのは「この土地とこの客に何を渡すと役に立つか」。「扱わないもの」は答えがそこに当たったときだけ参照し、紹介に使う。プロンプトでは、客の土地と店の設定を先に、扱わないものは末尾の参照として置く（私の意見）。
- **設定が黙っている所は、黙っていると言う。** その地点の土地勘が空なら、公開データから見立ては言うが、店の知見のふりはしない（私の意見）。

これらは `claudeai.html` の作り直しで、試作として示します。

## 5. 会話の組み立て（ユーザーへの質問で固まったこと）

**芯：どの一言も「次を引き出す」意図で出す（ユーザー）。** 意図のない広げ方は危険で、広げないほうがまし（ユーザー）。技を教え込むより、この意図一つを渡すほうがAIは対応できる（私の意見）。

- **提供データはドライ。その範囲だけで反応しない（ユーザー）。** 腕の良い営業は焦点をぼかす。周辺の出来事、行政、病院・公園・公共サービス。「当たらずとも遠からず」（ユーザー）。人柄などAIに無理な所は店の土地勘が担う（私の意見）。
- **ぼかしから土地へは、開いた問いでつなぐ。** 「住まいとして見たら」「この土地を今後どう考えるか」（ユーザー）。つなげられなければ「社に戻り検討します」以下（ユーザー）。人へ渡すときも、つなげて渡す（私の意見）。
- **AIの責任は情報収集。** 客がAIに感心しても不満を持っても、情報が取れていれば意味がある。最悪は、怒らせて何も取れない形（ユーザー）。だから、踏み込む前に集める（私の意見）。
- **客は二種類、どちらも店へ来る。** AIに感心して続きを聞きたい客と、「AIがこう言ったけど、お宅はどうなの」と聞く客（ユーザー）。どちらも客にとってプラス。
- **途中で電話が来ても使えるよう、一往復ごとにアクション履歴へ積む（ユーザー）。** 積むのは行動と言葉だけ。担当の見立ては店の業務記録で、客に見せる範囲は店が決める。
- **耳の痛い地域の話は、言い方ひとつ（ユーザー）。**

## 6. 試し方（私の案）

画面より先に、プロンプトを試す。見本の地点で最初の数往復を実際に出し、一言ごとに三つで判定する。
1. 何を引き出すつもりの一言か、言えるか
2. 客の土地か客の語ったことへ戻る糸があるか
3. 踏み込んだ一言の時点で、何が集まっているか
