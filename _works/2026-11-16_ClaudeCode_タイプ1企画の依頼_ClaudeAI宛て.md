## 現状（2026-11-16）

**動いているもの（タイプ2・3）**
- 流れ：都道府県・市区町村 → 地図にピン → 設問（道との関係・角・使い方、`survey.js` でタイプ2・3共通）→ 土地評価データの表 → AIとの対話 → 締めの一文 → メールで問い合わせ。
- タイプ3（AI型）：店が管理画面でボタンの段を作り、AIは「答える＋次のボタンが答えになる問い」で導く。
- タイプ2（対話型）：設問のあとは書き欄だけのふつうのチャット。
- 店の管理画面：店のHPのURLを入れると読み取り、「何をしている店か・得意な事情・連携する専門家・扱う地区と物件・営業時間」などを下書きにする（店が直せる）。AIはそれを「弊社のこと」として話す。
- 公開データ：国の地価公示・用途地域・周りの施設など。標準地との違いで足し引きする査定（角地・道幅・旗竿など）。
- 代替え地：客の言葉から「住み替え」などのきっかけを察知し、近くで同じ額で買える標準地を例として出す。
- 記録：画面の動き・会話・費用を全部残し、開発利用状況で見える。テストの記録はボタン一つで `_works` へ上がる。

**今日（11-16）の結果**
- ユーザーが10社のHPでタイプ3の初期設定〜対話を試し、AIの対応は全体に GOOD。
- 読み取りの取りこぼし（業務の案内ページを読んでいなかった、営業時間・物件の種類の欄がなかった）を直した。足りないときは空欄だけ読み直す。
- 店のHPは「健全」と言えるものが少ない（147社中10社ほど）。だからサンプルHPが健全性の見本になり、物件情報はその店の取り扱い・得意の表現として読む、というのがユーザーの見方。

## Claude Code が今考えるタイプ1

材料として置きます。採らなくて構いません。

1. **AIなし ≠ 判定なし。** 地図・設問・公開データの表・足し引きの査定・代替え地の候補・扱う地区の照合は、どれもプログラムで動いていてAIを使わない。タイプ1でも「データで言い切る」ことはできる。違いは、言葉で受け止めるかどうか。
2. **③から先は、店が作るフローチャート。** ボタン → 用意した文 → 次のボタン。管理画面は、タイプ3のボタンの段を「枝分かれ図」として編集する形が近い。
3. **書き欄の扱いが要の決まり。** 「書いた言葉には必ず答える」が今の決まり。AIのいないタイプ1では、書き欄を置かず、言葉は問い合わせに回す（「この内容で担当へ送る」）のが筋だと考えている。
4. **初期の枝はHPの読み取りから作れる。** 読み取りはAIを1回使うが、店の設定時の1回だけで、訪問者ごとの費用はない。「売り切り」と両立するかは確認したい点。
5. **価値の置き方の候補。** 費用が月々かからない／返事がぶれない／店の言葉がそのまま出る。弱いのは、用意していない話に答えられないこと。それを問い合わせの入口に変えられるか。
