# AI型 土地相談アプリの説明書 ― 対象事業所の拾い出し用
――Claude Code　2026-11-08

この書面は、「この機能で対応したい事業所」をウェブから拾い出す（スクレイピングで候補を集める）ときの判断材料です。前半で機能を短く説明し、後半で「どんな事業所が合うか」を、ホームページから読み取れる手がかりに置き換えています。

---

## 1. 何ができる機能か（ひとことで）

不動産会社のホームページに置く「土地の相談窓口」です。訪問者が自分の土地を地図で指し、いくつかの質問にボタンで答えると、公開データとAIの返事で、その土地の見立てが進みます。最後に「この情報をもとにお問い合わせ」で、相談の記録ごと店に届きます。

- 訪問者の側：相談する前に、自分の土地の条件（接道・用途地域・近くの公的な地価など）と、選べる道が分かる。
- 店の側：問い合わせが「土地の条件と本人の事情が整理された相談」として届く。電話で一から聞き取る手間が減る。

## 2. 流れ（訪問者の画面）

| 段階 | 中身 | 誰が答えるか |
|---|---|---|
| ⓪ | 都道府県・市区町村 → 地図 → 土地にピン → 面積 →「評価する」 | ― |
| データ | 公開データ（国土交通省「不動産情報ライブラリ」：地価公示・地価調査、用途地域）を表にする | 機械的に |
| ①〜③ | ロケーション（道への接し方・道幅・建物）。全業態共通 | 台本 |
| ④〜 | 店が選んだ業態のボタン（相談の目的など）。書き欄にも答える | AI（Claude） |
| 締め | 店の一手（「現地で一緒に絞ります」など）→ 問い合わせ | ― |

- AIは、店が書いたボタンの範囲でだけ話す。ボタンが尽きたら「詳しくは弊社へ」で打ち切る（往復の上限あり）。
- 売り逃げ・あおりには協力しない（立ち位置として固定）。法律・税・投資の最終判断はせず、専門家へつなぐ。

## 3. 店が選ぶ「業態モード」（4＋1）

ここが拾い出しの軸になります。④から先は、店がどの業態を選ぶかで変わります。

| | 呼び名 | ④から先で引き寄せる先 | 締めの一手（初期値） |
|---|---|---|---|
| 1 | 物件情報をいち早く届ける店（仲介情報屋） | 売り時・似た土地の動き・買い手がいるか | 近い条件の買い手の動きと、売り出しの段取りを持って伺う |
| 2 | 土地を買い取り、形にする店（開発優先） | 何が建つか・採算・お隣と合わせる・買い取り | 建てられる物と採算、買い取りの目安を出す |
| 3 | 土地の活かし方から一緒に考える店（総合系） | 住む・建てて貸す・建てずに貸す・売る・お隣と合わせる | 接道の条件で、選べる活かし方を現地で一緒に絞る |
| 4 | 相続や税の相談から始める店（相続・税） | 名義・家族の考え・期限・贈与か相続か | 名義と評価の整理から、司法書士・税理士と一緒に伺う |
| ＋1 | 一から自分で作る店 | 店が書く | 店が書く |

今の試作は3番（総合系）で動いています。

## 4. 合う事業所・合わない事業所

**合う（中心の対象）**
- 地域に根ざした中小の不動産会社で、**土地・戸建ての売却や活用の相談**を受けている。
- 自社のホームページを持ち、問い合わせフォームや査定依頼の窓口がある（この機能はそこに置く）。
- 対象の市区町村をはっきり書いている（商圏が決まっている）。

**合わない（外す）**
- 賃貸の部屋探しだけ、管理だけ、投資用マンションの販売だけの会社。
- 大手やフランチャイズの加盟店で、ホームページが本部の共通の作りになっている（店が独自に機能を置けない）。
- 自社のホームページがなく、ポータルサイトの掲載だけの会社。

## 5. ホームページから読み取る手がかり（業態の当たりを付ける）

ページの見出し・メニュー・本文に出る言葉で、どの業態に当てはまりそうかを推定します。1社に複数当てはまってよい（いちばん強いものを「推定モード」に）。

| 推定モード | 手がかりの言葉（例） |
|---|---|
| 共通（対象かどうか） | 土地、売却、査定、無料査定、空き家、古家付き土地、地域名＋不動産 |
| 1 仲介情報屋 | 売却専門、物件情報、新着物件、買いたい人がいます、購入希望者、売り出し、相場 |
| 2 開発優先 | 買取、即現金化、土地買取、分譲、建売、開発、用地募集、仕入れ、隣地 |
| 3 総合系 | 土地活用、有効活用、アパート経営、駐車場経営、建て替え、リフォーム、住み替え |
| 4 相続・税 | 相続、相続不動産、遺産分割、相続税、生前対策、贈与、名義変更、税理士・司法書士と提携 |

補助の手がかり：
- 問い合わせフォームの有無、「査定依頼」「売却相談」のページの有無（置き場所があるか）。
- 対象エリアの書き方（「〇〇市・〇〇町を中心に」）。今の試作は全国の地図とデータで動くので、地域は問わない。
- 更新が止まっている・作りが古いホームページは、作り直しの提案と一緒に入れやすい（HPパッケージ商品の構想と合う）。

## 6. 候補一覧に残す項目（案）

| 項目 | 中身 |
|---|---|
| 社名・所在地・URL | 基本 |
| 宅建業の免許番号 | 実在の確認用（国土交通省の宅地建物取引業者の検索で照合できる） |
| 推定モード | 1〜4（複数なら強い順） |
| 根拠の言葉 | 推定に使った言葉と、見つけたページのURL |
| 置き場所 | 問い合わせフォーム／査定ページの有無 |
| 除外の理由 | 4.の「合わない」に当たる場合 |
| メモ | ホームページの古さ、対象エリアなど |

## 7. 集めるときの注意
- 各サイトの利用規約と robots.txt に従い、間隔をあけて読む。ポータルサイトなど、自動での取得を禁じている所からは集めない。
- 集めるのは会社の公開情報だけ（社名・所在地・URL・ページの言葉）。個人の情報は集めない。
- 一覧は営業の候補であって、送り先の名簿ではない。連絡の仕方は別に決める。

## 8. いまの段階（候補に話すときに正直に言うこと）
- 試作の段階。公開テストの準備中で、URLを送って自由に試してもらう形を予定している。
- 公開データは、国の窓口のキー待ち（11-13ごろの見込み）。それまでの表の数字は見本。
- 価格の考え方（ユーザー決定、11-03）：客のデータを店への通知メールに添えるだけでアプリに溜めない形が基本（50,000円）。データベースや統計まで望む場合は、預かる責任の分を乗せる（500,000円）。
- AIの費用の目安：1回の相談で数円〜十数円（11-08 の歯止め：1日 $2 で相談40〜50件ほど）。
