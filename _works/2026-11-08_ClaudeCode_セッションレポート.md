# 2026-11-08 セッションレポート（Claude Code）

APIセッション（公開画面での通しテスト）の最中に受けた直しと、一般公開に向けた準備をまとめる。
公開中のサーバーは、このレポートの時点で再起動済み（すべて反映済み）。

## 1. 画面の直し（テスト中の指摘）
| 指摘 | 直したこと |
|---|---|
| 書き欄の例の文が「（例：：」で切れる、入力がはみ出す | 書き欄は書いた分だけ縦に伸びる（メイン画面・管理画面の長い文の欄） |
| 自分の吹き出しの2行目が右詰め | 吹き出しは右寄せのまま、中の文は左から折り返す。改行も表示 |
| ①〜③でも書いて答えたい | ①②も「選ぶ＋書き欄＋送信」。ボタンなしで書いた場合は「書いていただいたことは、このあとの見立てに入れます。」で③へ。書いた言葉はデータシートの「事情」に残り、③→④のAIに渡る |
| 送信が押せる状態を目立たせたい | 送信は押せるときに青地・白文字（反転）。押せないときはグレー |
| 開発利用状況で、費用が出たものだけ見たい | セッション表に「□費用が発生したものだけ」（対象の前） |

## 2. 公開データ（国土交通省「不動産情報ライブラリ」）— 見本で先に作った
- APIは申請済み（個人名義、審査の結果は11-13ごろの見込み）。キーが届くまでは、サーバーが実在しない「見本」の値を返す。値には（見本）と付ける。
- データの表は19行：この土地（所在・面積・用途地域・建ぺい率と容積率・道への接し方・形と向き）／最寄りの標準地（地点・種類・価格・前年から・広さと形・使われ方・周りの様子・前の道・最寄り駅・水道ガス下水・区域と規制）／目安（単純計算）。決まっていない行は「未定（下の①②で伺います）」など。①②に答えると、その場で埋まる。
- 表の下に、国が決めた出典の一文を出す。
- サーバーからだけ国の窓口を呼ぶ。取ったデータは30日保存して使い回す。呼ぶ間隔は0.4秒。画面は12秒で諦めて「未定」で進む。
- AIへの指示：見本の間は「（見本）の値は伝えない」。本物になったら「標準地の価格は別の土地の値。この土地の値段として言い切らない」に切り替わる。

## 3. 同時に使われたときの強さ（一般公開に向けて）
**測った結果（AIは呼ばずに測った。費用なし）**
- 画面の記録（動き・保存）：100人が同時に使っても、遅い方5%で51ミリ秒、失敗0、メモリ35MB（上限256MB）。
- 詰まるのはAIの部分だった：同時4件を超えると断っていた。1日 $2 で止まる（相談40〜50件ほど）。

**入れた歯止め（開発利用状況の「設定」→「公開テストの歯止め」で、再起動なしに変えられる）**
| 歯止め | 最初の値 | 中身 |
|---|---|---|
| 同時に使える人数 | 10人 | 入口＝「地図を開く」で判定。使用中＝最後の操作から15分以内。止めたら「利用数の上限に達しているため、しばらく時間をおいてから操作してください。」 |
| 1日のセッション数 | 50件 | その日に「地図を開く」で入った数 |
| 1日の費用上限 | $2 | 超えるとその日のAIは止まり、台本の文だけになる |
| 同時に処理するAIの数 | 4件 | 超えた分は断らず、最大25秒順番を待つ |

一度入ったセッション、再表示、デモは止めない。設定を変えた履歴と、今日止めた数が見える。

**ついでに直したこと**
- AIへ渡す説明の上限が2,000字で、データの表が加わると末尾の指示が切れるおそれがあった → 6,000字に上げた。
- 長い会話で問い合わせがあふれるおそれがあった → 受け取れる量を32KBから256KBに上げた。
- データシートの保存が24項目までで、新しい表で23項目とぎりぎりだった → 40項目に上げた。

## 4. 送信と原文（試験用）
メイン画面のAIの返事ごとに、折りたたみの欄を付けた。①送ったもの（システムの指示＋会話の全文）、②画面に出した返事、③AIの原文（止まった理由・トークン数・秒数）が1組で見られる。切り捨てや、回答が途中で切れた場合、つながらなかった場合は、赤で「あふれ・異常あり」と出る。記録（再表示）には入れていない。

## 5. 確かめ方と結果
- 公開中の画面：見本の値と①の答えが表に入った。再表示で新しい表の形に戻った。
- 入口の制限・AIの順番待ち・あふれの表示：公開中とは別の試験用サーバーと、AIの代わりの見本で確かめた（費用なし）。12人が同時に問い合わせても断りは0件で、順番に返事が来た。上限を変えるとその場で効いた。打ち間違い（$50など）は保存されなかった。
- 国の窓口のデータの読み取り：説明書どおりの形の偽のデータで確かめた（最寄りの地点、ピンの場所の用途地域、前年への切り替え、2回目は保存した結果を使う）。**本物のデータでは、キーが届くまで確かめられない。**

## 6. 懸案（決まっていないこと）
1. **返事の「点検と作り直し」を、商品の段階として持つ**（ユーザーと合意、まだ作っていない）。段階の案：標準（なし）／点検つき（決まりで点検し、外れたときだけ1回作り直す）／見直しつき（毎回AIに見直させる。費用と時間がほぼ倍）。契約で決まるものなので、店の管理画面ではなく運営側の設定にする。AI型と、これから作る「ボタン選択式」の両方で使える部品にして、「形態」×「段階」で商品の差を作る。
2. 「単純計算（標準地の価格×面積）」の行を残すか（Claude Code のおすすめは外す）。
3. キーが届くまで、公開画面で見本の値を出すか、訪問者には「未定」だけを出すか。
4. 書き欄に文字数の上限を付けるか（7,000字書くと、末尾の指示が切れる）。
5. 公開テストの前に：Console の「Limits」を確かめて、同時に処理するAIの数をどこまで上げるか決める。人が多い日は1日の費用上限も上げる（目安：同時20人なら $10）。月の使用上限を先に決める。
