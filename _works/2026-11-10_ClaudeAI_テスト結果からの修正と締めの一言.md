## 4. 追記（19:40 ユーザーと相談）：AIの目線を2種のモードに

ユーザーの案：タイプ2の「外の人のAI」をそのまま売るのは、買い手の不動産屋に伝わりにくい（「HPの中で他人が答える？」）。そこで **AIの対応目線を2種のモードにする**。

- **社員目線**：今のタイプ3の声。「弊社」と呼び、確かめることを引き受ける。
- **第三者目線**：店が置いたAIだが、外から見た目線で話す。HPの情報（店の広告）に加えて、Web上の書き込みなど外の情報も示す。

売り込みでの説明は「セッション内のAIが、HPの広告とネットの情報の両方を示す仕組みを備えている」程度にとどめ、2種のモードの違いとして出す。
第三者目線に中身が出るのは、Webの書き込みを抽出したデータがあるとき（抽出はユーザーの仕事として提供する構想）。

### 4-1　決めたこと（法律の線から）

ステマ規制（2023年10月〜、景品表示法の告示）は「事業者の表示なのに、第三者の表示に見せること」が対象。だから：

1. **AIは独立した第三者を名乗らない。** `system_talk.txt` の書き出し「その会社の人ではありません」は、「〇〇不動産が置いたAIですが、外から見た目線で話します」の趣旨に書き換える。画面にも「このAIは〇〇不動産が設置しています」を出す。
2. **AIは店を「信頼できる」と判定しない。** 「Webにこういう書き込みがあります」と出どころを付けて示し、どう見えるかは利用者に返す（「AIを評価者にしない」とも一致）。
3. **書き込みは良いものだけを選ばない。**（抽出側の決まり。データの仕組みは未定）

### 4-2　Claude.ai の考え：違いは「口調」ではなく「構造」で作る

ユーザーの課題は「この微妙な対応差を API ができるか」。口調の微妙な差で分けると、ぶれる。構造の決まりで分ければ、守れるし確かめられる。

| | 社員目線 | 第三者目線 |

| 自分の呼び方 | 弊社 | 呼び名で外から（〇〇不動産） |
| 約束・引き受け | する（「弊社が現地で確かめます」） | しない |
| 情報の出どころ | 書かなくてよい | 文中に必ず付ける（「HPによると」「Webの書き込みでは」） |
| 締め（3章） | まだ決まっていない点を名指しして、引き受ける | 同じ点を名指しして、店へ持っていく問いとして渡す |

## 5. 追記（19:59 ユーザーと相談）：管理画面で2つの目線の違いを見せる

### 5-1　決まったこと（ユーザー）

- 管理画面は両目線で共通。**URLを指定すると項目が埋まる（デフォルト値）→店が直す**、という手順。
- **URLから項目を埋めるプログラムに発展させることが、2つの目線を両立させる条件。**
- 違いは、プログラムとして分かりやすく見せる。例：**第三者目線では、大命題のプロフィール（店の基本像）は指定したHPから作り、管理画面では変更できない。** これが第三者目線の定義そのもの。

### 5-2　Claude.ai の考え

- 第三者目線の中身は「店の申告を伝える」ではなく、**HPの中身から利用者にとっての合う・合わないを、根拠（HPの何を見たか）付きで読み解く**こと。例：「この会社のHPは事例の多くが相続がらみ。相続のからむ土地なら話が早い。投資用の話は事例が少なめ」。広告目線は同じ材料から強みの文を作る。

### 5-5　広告目線の管理画面：デフォルトの「手直しの視点」（Claude.ai）

ユーザーの問い：第三者目線の次に、広告目線でデフォルトをどう手直しさせるかを想像する。
前提：広告目線では、URLから埋めた欄を店が書き換えられる。問題は「何を手がかりに直すか」。白紙の欄と同じで、手がかりがなければ店は「誠心誠意」「お気軽に」を書く。

**視点1　HPの読み物を、会話の材料に変える（プログラムの仕事）**
HPの文は読ませるための文、AIに要るのは話すための材料。デフォルトは HP の文の写しではなく、項目ごとに「AIがこう言える」形に直して入れる。
例：HP「地域密着30年」→ 欄「長良地区で30年。この辺りの土地の昔の使われ方を知っている」

**視点2　形容詞を事実に変える（店の手直しの手がかり）**
欄の横に「この言葉は、AIが会話でそのまま言います」と出し、形容詞（安心・丁寧・地域No.1）には「件数・地域・年数で言えますか？」と問いを添える。
あわせて、AIに言わせられない言葉（最安・No.1・必ず売れる 等）は、根拠がなければ印を付ける。広告目線のAIの言葉は店の広告なので、景品表示法や宅建業法の誇大広告の禁止（32条）がそのまま掛かる。判定はせず「根拠を書いてください」まで。

**視点3　引き受けを具体にする（締めを強くする手直し）**
3章の締め「弊社が現地で〇〇を確かめます」は、デフォルトのままだと誰でも言える。手直しで、店が本当に引き受けられる中身を書かせる。
例：現地を見るのは無料か／何日以内に行けるか／誰が行くか（宅建士か、代表か）
→ このテストで出た課題「問い合わせの可能性が上がる程度」への、広告目線側の答えになる。

**進化の形：第三者目線の読み解きを、広告目線の「鏡」に使う**
同じURLの読み取りから第三者目線の読み解き（合う・合いにくい相談、業態の判定）はいつも作れる。広告目線では鍵をかけず、各欄の横に**「外からはこう見えています」**と参考として出す。
- 店が選んだ業態とHPからの判定が違えば、そのずれを見せる（「あなたは開発優先を選びましたが、HPは仲介情報屋に見えます」）
- 直すのは店の自由。ずれを埋めたければ、欄ではなくHPを直す道もある → HP修正の注文
- つまり、どちらの目線を選んでも、URLの読み取りが「店の手直し」と「HP修正」の両方の入口になる

| | 広告目線 | 第三者目線 |
|---|---|---|
| URLの読み取り | 初期値＋「外からの見え方」を参考に表示 | 初期値＝確定（鍵） |
| 店の手直し | 自由。手がかり＝視点1〜3と「外からの見え方」 | 「店からの一言」だけ |
| HP修正への入口 | 見え方のずれ | 鍵のかかった欄 |

| 引き受けの中身（現地を見るのは無料か／何日以内／誰が行くか） | 締めの「弊社が確かめます」が具体になる | 書いた内容は約束になる |
| この辺りの土地勘（昔の使われ方、水が出た所、人気の学区など） | 公開データにない「当たらずとも遠からず」の一言が言える | 地域を悪く言う言い方はAI側で避ける |
| 受けない相談・回す先（税理士・司法書士などの連携先） | 断るときも利用者を手ぶらで帰さない | — |
| 今の買い手の待ち（この地区で土地を探している人がいる、など） | 売り手の利用者に一番強い締めになる | **実在しない買い手を書くとおとり広告になる（宅建業法）**。更新日を必須にし、古くなったらAIは使わない |
| 連絡の受け方（時間帯・連絡手段・誰が出るか） | 「電話の後」の不安を減らす（商品の狙い＝電話を取りこぼさない） | — |

**第三者目線での見え方**
これらの欄は空白で鍵がかかり、「HPに書かれていないため、外の目には見えません」と出す。横に「HPに載せれば、第三者目線でも使えます」。

**Claude.ai の考え：空白の鍵付き欄は、そのまま「HPに足りないもののリスト」になる**
- 第三者目線を選んだ店は、空白欄の数だけ「HPに載せれば会話が強くなるもの」を目で見ることになる。
- これはHP修正の提案書そのもの。営業で「御社のHPは、外の目からはここが空白です」と見せられる。
- 広告目線の店も、自分で埋めた欄のうちHPに無いものが分かる（5-5の「鏡」と同じ働き）。
