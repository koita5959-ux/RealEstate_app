## 1. 決定：バグ修正（2件）

### 1-1　回答文の土地面積が違う（タイプ3・総合系、最重要）

見立て（コードから）：`aiContext()` は データシートを全部並べて渡すので、AI には
- `面積：〇〇㎡`（利用者の入力）
- `標準地の地積と形：200㎡・間口：奥行き＝…`（**近くの別の土地**の広さ）

が並ぶ。【公開データ】の注意は「標準地の価格はこの土地の値段ではない」だけで、**広さ**には触れていない。AI が標準地の地積を利用者の土地の面積として話した可能性が高い。

直し方（案。より確かな方法があればそちらで）：
1. 【公開データ】の注意に「この土地の面積は『面積』の値だけ。標準地の地積は別の土地の広さで、この土地の話に使わない」を足す（`3_ai_main.html`・`2_talk_main.html` の両方）。
2. AI へ渡す項目名を取り違えにくくする（例：`面積` → `この土地の面積（利用者の申告）`、`標準地の地積と形` → `標準地（別の土地）の広さと形`）。画面の表示名は今のままでよい。
3. 確認：その回の「送信と原文（試験用）」で、取り違えの原因がこれで合っているかも見てください。違えば原因の報告を。

### 1-2　④の「建物にも値打ちが残る見方は十分ありえます」

ユーザー：意味が分からない。手放す前提なら安くなる話なので、「建物にも評価がつくことは十分考えられます」のような言い方が妥当。

直し方：`system.txt` に決まりを1行。
「建物や土地の価値の話は『評価がつく／つきにくい』のような、利用者が普段使う言い方にし、『値打ちが残る』のような含みのある言い方をしない」
（言い回しはお任せ。狙いは、売り手の利用者が誤解なく受け取れること）

## 3. 提案：締めの一言で「問い合わせる根拠」を渡す

### 3-1　見えた課題

タイプ3の「可能性が上がる程度」と、タイプ2の「聞いてみる根拠にならない」は、根が同じ。
今の AI は最後を「店に聞いて」で終える（最後の返事は「問いかけも付けず、打ち切りは画面が添える」）。**この土地の何がまだ分からず、なぜそれは店でないと決まらないのか**を言っていない。

### 3-2　タイプ3（AIは店の声）

最後の返事（`n >= LIMIT`）の指示を変える。
- 今まで集めたデータシートのうち、**まだ決まっていないこと**を1つ名指しする（例：前の道が4m未満かどうか、境目が確定しているか、建物に評価がつくか）
- それが**現地を見ないと決まらない理由**を一言
- 「弊社が現地で〇〇を確かめます」で締める（約束できるのは店の声だから）

### 3-3　タイプ2（AIは外の人）— ここがユーザーとの相談の中心

外の人の AI は、店の代わりに約束できない（`system_talk.txt`：会社の代わりに約束しない）。だから「〇〇に聞いてみて」以上の詰めが言えない。これは設定を店寄りにしても越えられない、**立ち位置そのものの限界**、というのがユーザーの見立て。

Claude.ai の考え：外の人には、店の声にできない詰め方がある。**「店へ持っていく問い」を渡すこと。**
- 例：「この土地なら、〇〇不動産に『前の道が4m未満かを現地で見てもらえるか』と聞くと、売るときの話がはっきりします」
- 約束はしていない（店の代わりに答えていない）。それでも、電話する理由が利用者の手に残る。
- 店のURLの情報（得意分野）と、この土地の未決の点が合えば「この件は〇〇の得意なところ」と、外から根拠を添えられる。店の声で言うと売り込みに聞こえることが、外の声だと口コミになる。
- 店にとっても、問いを持った相談が来る（データシートと一緒に）。

※ユーザーとまだ相談中。この方向で決まったら改めて依頼します。Claude Code の考え（タイプ2の役目をどう見るか）も聞かせてください。

## 4. 追記（19:40 ユーザーと相談）：AIの目線を2種のモードに

ユーザーの案：タイプ2の「外の人のAI」をそのまま売るのは、買い手の不動産屋に伝わりにくい（「HPの中で他人が答える？」）。そこで **AIの対応目線を2種のモードにする**。

- **社員目線**：今のタイプ3の声。「弊社」と呼び、確かめることを引き受ける。
- **第三者目線**：店が置いたAIだが、外から見た目線で話す。HPの情報（店の広告）に加えて、Web上の書き込みなど外の情報も示す。

売り込みでの説明は「セッション内のAIが、HPの広告とネットの情報の両方を示す仕組みを備えている」程度にとどめ、2種のモードの違いとして出す。
第三者目線に中身が出るのは、Webの書き込みを抽出したデータがあるとき（抽出はユーザーの仕事として提供する構想）。

### 4-1　決めたこと（法律の線から）

ステマ規制（2023年10月〜、景品表示法の告示）は「事業者の表示なのに、第三者の表示に見せること」が対象。だから：

1. **AIは独立した第三者を名乗らない。** `system_talk.txt` の書き出し「その会社の人ではありません」は、「〇〇不動産が置いたAIですが、外から見た目線で話します」の趣旨に書き換える。画面にも「このAIは〇〇不動産が設置しています」を出す。
2. **AIは店を「信頼できる」と判定しない。** 「Webにこういう書き込みがあります」と出どころを付けて示し、どう見えるかは利用者に返す（「AIを評価者にしない」とも一致）。
3. **書き込みは良いものだけを選ばない。**（抽出側の決まり。データの仕組みは未定）

### 4-2　Claude.ai の考え：違いは「口調」ではなく「構造」で作る

ユーザーの課題は「この微妙な対応差を API ができるか」。口調の微妙な差で分けると、ぶれる。構造の決まりで分ければ、守れるし確かめられる。

| | 社員目線 | 第三者目線 |
|---|---|---|
| 自分の呼び方 | 弊社 | 呼び名で外から（〇〇不動産） |
| 約束・引き受け | する（「弊社が現地で確かめます」） | しない |
| 情報の出どころ | 書かなくてよい | 文中に必ず付ける（「HPによると」「Webの書き込みでは」） |
| 締め（3章） | まだ決まっていない点を名指しして、引き受ける | 同じ点を名指しして、店へ持っていく問いとして渡す |

確かめ方の案：同じ土地・同じ入力で両モードを本物のAIで通し、上の表の4行が返事に出ているかを見る。

Claude Code へ：この分け方で API の返事が安定するか、実装する側の見立てをください。
