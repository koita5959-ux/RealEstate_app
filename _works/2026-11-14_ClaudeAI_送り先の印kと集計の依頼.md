# 送り先の印（`&k=`）と送り先ごとの集計の依頼

- 作成：Claude.ai（構想立案プロジェクト）　2026-11-14
- 宛先：Claude Code（RealEstate_app）
- 位置づけ：`_works/2026-11-14_ClaudeCode_AIボット不動産_HP制作企画書.md` 10章の課題「送り先ごとの印（`&k=…`）を付けるか」への回答。付ける
- ユーザーの狙い：開発の利用と営業先の利用を分けて合算し、**どの送り先がどこまで試し、APIにいくら掛かったか**を見られるようにする

---

## 1. 送り先リスト（事前準備）

地区一覧と同じく、メールを送る前に作って人が確かめる資料にする。

| 列 | 中身 |
|---|---|
| k | 送り先の番号（例 `a07`）。推測されにくい短い文字列でもよい |
| 業者名・HPのURL | 41件（`_works/2026-11-09_ClaudeAI_タイプ別サイトのサンプル41件.csv`）から |
| 業態 | 41件に付けた札 |
| 地区ID | 業者の所在地から地区一覧の逆引きで決める |
| 送るURL | `…/sample/?r=地区ID&k=番号` |

- **記録（ログ）に入るのは `k` の番号だけ。** 「番号＝業者名」の対応はこのリストだけが持つ
- 業者のメールアドレスを列に足す場合、そのリストは GitHub に上げない（サーバーか手元に置く）。業者名とURLだけなら `_works/` でよい

## 2. 記録への `k` の追加

- ページは URL の `k` を読み、`sid` と同じように各リクエストでサーバーへ渡す
- サーバーは `log-日付.jsonl` と `events-日付.jsonl` の各行に `k` を書く（企画書7章の地区IDと同じ扱い）
- `k` がないアクセス（転送されたURL・直接の訪問）は「k なし」として別にまとめる。開発の利用（`by` が visitor 以外）とは混ぜない

## 3. 開発利用状況での見え方

送り先ごとに1行：

> k=a07（地区 23-1）｜開いた → ピン → 何往復 → 締めまで → 問い合わせ送信｜API費用 $0.xx

- 「業者名」は画面に出さなくてよい（ユーザーが送り先リストと突き合わせる）
- 合計行：営業先の合計費用／開発の合計費用を分けて出す

## 4. 送る前に確かめてほしいこと（重要）

今のサーバーには1日の上限がある（`limits()`：費用 `dailyCap` $2、利用者 `maxUsers` 10、セッション `dailySessions` 50）。

- メールを一斉に送ると、開いた業者が同じ日に重なり、**上限で途中から止まる**おそれがある。業者が触っている最中に止まるのが一番の失点になる
- 開発利用状況の記録から「1セッションの平均費用」を出し、送る件数と掛け合わせて、送る日の上限をどうするかをユーザーに提案してほしい（上限を上げる／分けて送る）
- 上限で止まったときに業者に見える画面も確認してほしい（「混み合っています」で終わらず、問い合わせ欄へつなげるのが望ましい）
