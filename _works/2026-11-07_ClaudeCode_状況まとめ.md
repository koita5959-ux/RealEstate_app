## 2. メイン画面の流れ（今の形）

都道府県・市区町村（例：東京都／千代田区）→ 地図を開く → ピン（住所が「東京都中央区日本橋茅場町二丁目付近」の形で出る）→ 面積（空欄から）→ 評価する → ①〜③（台本：接道→前の道→建物）→ ④ 相談目的（店のボタン＋書き欄。ここから AI）→ ⑤以降（店のボタンがなくなったら書き欄だけ）→ 往復の上限で「AIはここまでです。詳しいご相談はメールを…」→ お問い合わせ（送ると欄はグレーのまま残り「送信しました。担当者からのご連絡をお待ちください」）。

訪問者に見える自社の呼び方は「弊社」。

## 3. 今日（11-07）決まったこと・直したこと

ユーザーの方針として決まったこと：

- **全画面リアルタイム**：利用状況と開発利用状況は、メイン画面の動きのたびに変わる（公開テストで、案内した相手の動きをその場で見るため）。別のパソコンの動きも数秒で入る。
- **推定と実績**：開発利用状況は Claude Console の数字に合わせる。推定＝トークン数×単価。実績＝Console の日ごとの金額を、その日の往復へ推定の割合で割り振った額。トークン数は Console とぴったり合うはずなので、記録の漏れを確かめる材料にする。
- **再表示**：開発利用状況の行を押すと、開いているメイン画面がその体験の画面に戻る。今日のテストで、①〜⑦の会話・選んだボタンの点灯・書いた言葉まで戻ることを確かめた。
- **押し直しの扱い**：「地図を開く」「評価する」は、押したあとグレーで押せない（場所・ピン・面積が変わると点灯）。AI の返事を待つ間は、上の行の「別の道を試す」ボタンも押せない。

直した不具合：AI の返事が空になることがあった（長さの上限 600 トークンを、AI が考える処理で使い切っていた）→ 上限を 2000 に。

## 4. 懸案（実装の価値ありと合意済み）

**公開データを国土交通省「不動産情報ライブラリ」の API でつなぐ。** 今は岐阜市中心部の仮5地点しかなく、ほかの場所では「データなし（公開データは準備中）」になる。地価公示・地価調査の地点（XPT002）と用途地域（XKT002）を使う。無料。ユーザーの利用申請待ち（審査 約5営業日）。画面に決まった出典の一文が必要。データが入れば、AI も実際の数字を前提に話せる。

## 5. 次の通しテストで確かめること

- 今日の直しが効いているか（ボタンのグレー、AI の返事待ち、ピンの住所、空欄の面積、データなしの言い方）。
- お問い合わせまで進めて送り、そのあと再表示で、送った状態まで戻るか。
- **お問い合わせの入力内容を記録に残すか（ユーザー判断待ち）**：ユーザーは「入力内容で確かめたい」。今は画面に「記録もしません」と書いてあり、送ったことと連絡の希望だけを残している。残すなら注意書きを変える。本物の名前・連絡先が入ったときの扱い（試用後にログを消すか）とセットで決める。
