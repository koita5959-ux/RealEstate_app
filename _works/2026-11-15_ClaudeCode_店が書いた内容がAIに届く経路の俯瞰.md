# 店が書いた内容がAIに届く経路の俯瞰（2026-11-15 Claude Code）

目的：店に「書いた内容をAIが話していない」と言われないために、今の構造を俯瞰しておく。今回は修正しない。今後の修正で流されないための地図。

## 経路

1. URL → `server/shop/read.js`（トップ＋1段、最大3ページ）
2. → `server/shop/understand.js`（AIが下書きJSON：what / good / fit / unfit / stance / area …）
3. → 管理画面。店が直した欄＝`own`、書き足した欄＝`extra`（`docs/js/shophp.js` の SHOP_EXTRA）
4. → `docs/2_talk_main.html` の `talkShopBlock()` が文章にし、`contextFixed` としてサーバーへ
5. → `server/server.js:329` で `【店のこと】` としてAIの指示に入る

## 「書いたのに出ない」が起きうる所

| # | 所 | 内容 |
|---|---|---|
| A | 外野目線（タイプ2初期） | `own`・`extra` を渡していない。渡すのはHPの読みと「一言（memo）」だけ。店が欄を直しても、このモードでは届かない |
| B | 保存場所 | `own`・`extra` はブラウザの localStorage（`reShopKnow`）。別の端末やブラウザでは消える |
| C | 使う場面の指示 | 「重なりを探す」の明示は①〜③の返事と締めだけ。途中の往復では、関わる話が出たときに使うだけ |
| D | 返事の長さ | 150字・3文・問い1つ。1回の返事で出せる店の情報は1〜2点 |
| E | 長さの上限 | `contextFixed` は6000字で切る |
| F | 確かめ方 | どの欄が返事に使われたかの記録がない（送った文はログにある） |

## 考え方（今後の修正の軸）

- 店が書く欄ごとに「どこで効くか」を決め、管理画面でその欄の横に見せる。
  区分の例：毎回効く／場面で効く／話し方に効く／聞かれたら効く／このモードでは使わない
- SHOP_EXTRA の4つ目の値（「AIはこれに触れません」など）が、すでにこの役目の芽。HPの読みの欄（own）にも広げる。
- 「全部を会話に出す」ではなく、「出る場面を店が予想できる」ことを約束にする。

## 確かめが要ること

- A：外野目線のとき、管理画面が店に欄の直しをさせているか（させているなら、届かないことを画面で伝える必要がある）

## 次の作業：指定URL読み込みテスト（決めた進め方）

1. ユーザーがサンプルURLを10件前後選ぶ。各URLに「Type2/3」と「見た印象（正解）」を1行添える
2. 今の read.js・understand.js のまま読む（直す前の基準）。読めたページ・物件ページの作り（ふつう／JS表示／外部埋め込み）・AIの判断を一覧にし、項目ごとに「会話に効く／効かない」の印を付ける
3. 一覧をもとに相談し、直す範囲を決める。候補：業務リンク（売りたい・買いたい・相続・管理）の枠、「取扱物件」を事例から外して物件の枠にする、物件から売買/賃貸・種別・エリア・件数を数えて事実として渡す
4. 直して同じURLで読み直し、前後を比べる

## 追記：物件情報の取り込み（11-15 ユーザーと合意）

- 範囲：**売買のみ**。目的は「どういうものを扱っているか」をつかみ、会社の取り組みの情報（what・good・area）へ反映すること。これが拾えれば「サイトに対応」として成立する。
- 拾うもの：売買の物件の種別（土地・戸建て・マンション・事業用）、所在地（町まで）、目立つ言葉（古家付き・農地・分譲地など）、件数、読んだ日。価格・面積は種別の見分けに使える範囲で。
- 出し方：管理画面で「物件から：…」の候補として、店が書いた欄の横に出し、店が認めた分だけ使う。文章との食い違いはそのまま見せる。
- 探し方（トップに物件がないとき）：メニュー・フッター・画像の alt → sitemap.xml → 1段奥（売りたい・買いたい）→ よくある置き場所（/bukken/ など）→ 外の物件システム・ポータルのリンク（ポータルは読まず「掲載先」として残す）→ リンク一覧だけAIに選ばせる。見つからないことも業態の材料。
- 読み方：構造化データ → 決まりで抜く → AI（安いモデル）→ ブラウザ表示待ち → 物件システム別の読み口。読めなければ管理画面で貼り付け・URLを聞く。
- 今はしない：店の在庫を代替え地の候補にする・近くの売り物件の単価との比較（目的の外。必要になったら）。
- 10社テストで記録：物件にたどり着けたか／どの探し方で／どの読み方で／種別が分かったか。
- 補足（ユーザー）：物件の掲載は「買いたい」連絡を受けるための撒き餌で、在庫とは限らない。それでもプロフィールには使う。欲しいのは件数ではなく**「どの地区に、どういう物件がある（得意としている）」**の組で、AIの返事に反映するための情報源。形の例：「○○町・△△地区：古家付きの土地」「郊外：農地つき・広めの土地」。AIは客のピンの地区と照らして使い、個別の物件は紹介しない。
