# 戻り値のデータ化とロケーション強化 ― 実装報告

2026-11-11（夜）　Claude Code
もとにしたもの：ユーザーとの対話（11-11）。プログラムの価値は、AIの返事をデータとして受け取り、判定し、次に生かす所にある。まず戻り値をデータにし、送る中身を整え、ロケーションの材料を足す。

## 1. 返事を「表示する文＋引き継ぐメモ」に分けた（タイプ2・3共通）

- AIは返事の後ろに【メモ】と1行のJSONを書く。欄は5つ：分かったこと／まだ決まっていないこと／引き出せたこと／次に聞くとよいこと／店へのひとこと。
- サーバーがメモを切り離す。画面には返事だけを出す。メモはログに残し、画面にも返す。
- 画面はメモを次の往復に渡す（「これまでのメモ」）。メモがあれば、会話の全文は直近3往復だけ送る（前は10往復）。
- メモはデータシートの「AIのメモ」にも入るので、店へ添える記録になる。
- 送信と原文の欄・書き出しのテキストに、メモも出る。

実例（タイプ3、3往復）：利用者が「近所は静かで、桜並木がきれいな所なんだけど」と書くと、メモの「引き出せたこと」に「近所は静かで桜並木がきれい。土地への愛着がありそう」、「店へのひとこと」に「静かな環境と桜並木は買主像づくりに使える」と残った。

## 2. 送る順を並べ替え、キャッシュを使った

- 決まり（system*.txt＋メモの決まり）と店のことを前に置き、キャッシュに載せる。往復ごとに変わる状況（土地の条件・周り・この返事の指示・メモ）は後ろに置く。
- 店のこと（HPの読み＋店が書いた欄）は、画面から contextFixed として別に送る。
- 費用の計算に、キャッシュの書き込み（1.25倍）と読み込み（0.1倍）を入れた。

| 1往復あたり | 入力 | キャッシュ読み | 出力 | 費用 |
|---|---|---|---|---|
| 前（11-11 ユーザーのテスト 21回） | 3,405 | 0 | 502 | $0.0237 |
| 後（メモ＋キャッシュ 16回） | 1,090 | 2,150 | 686 | $0.0205 |

メモの分だけ出力が増えたが、入力の大半がキャッシュ読み（1割の料金）になり、1往復は約13%安くなった。説明を厚くしても、費用は増えていない。

## 3. ロケーションの材料（作業用データ。画面の表には出さない）

`GET /api/around`（server/around.js）。ピンの周りを無料のデータで読む。

| 見るもの | 出どころ |
|---|---|
| 最寄りの駅2つ（路線・直線距離・乗降客数） | 不動産情報ライブラリ XKT015 |
| 小学校区・中学校区 | XKT004・XKT005 |
| 洪水・高潮・津波・土砂 | XKT026〜029 |
| 人の増減（250m四方、2025→2045年） | XKT013 |
| 区域区分・居住誘導区域 | XKT001・XKT003 |
| スーパー・コンビニ・ドラッグストア・ショッピングセンター・ホームセンター | OpenStreetMap（中部のファイル。`server/poi_extract.py` で月1回ほど作り直す。14,550件） |

- 初回は5〜7.5秒。取ったタイルは30日保存するので、2回目からは速い。画面の表とは別に後ろで取るので、表の表示は待たせない。
- AIへの決まり（docs/js/around.js）
  - 周りは買う人・借りる人の物差し。持ち主に「買う人の目」として渡し、上げも下げもしない。
  - 1つの返事で触れる周りの事実は1つまで。出どころと直線距離で言い、徒歩何分・「駅近」とは言わない。
  - 事実を渡したあと、持ち主の方が詳しいことを1つ聞いてよい。答えは「買う方に伝わる良さ」として受け止める。
  - 店の名前は、渡したものだけを使う。「近くにない」とは言わない。
  - 人の増減・居住誘導区域は、急かさず、考える時期の手がかりとして言う。
- 主に見るもの（レンズ）を、用途地域と相談の目的で切り替える。
  - 用途地域：住まい／商い／仕事（工業・工業専用）。準工業は住まいとして見る。
  - 相談の目的：売る＝学区・駅・暮らしの店、貸す＝駅と乗降客数、残す・迷う＝人の増減・居住誘導区域・災害。

## ユーザーにお願いするテスト

1. **会話の見え方**：前と変わらないか（メモの文字が画面に出ていないか）。
2. **土地勘のある場所でのロケーション**：駅・店・災害の言い方が当たっているか、「賢い」と感じるか。
3. 気になったセッションは、利用状況の「テキストで書き出す」で _works へ。書き出しには「店のこと」「AIへ渡した説明」「AIが書いたメモ」が入っている。

## 気づいていること（まだ直していない）

- OpenStreetMap の分類の誤り（名古屋の「スーパービバホーム」はホームセンター、アピタが百貨店にも入る）。AIには「誤りがありうる」と添えて渡している。
- ①〜③の返事で、周りの事実は添えるが、場所についての問い（引き出し）はまだ出にくい。①〜③の返事は次のボタンにつなぐ問いで終える決まりがあるため。引き出しは④から先の方で出る。
- 選び直し（1段の開き直し）をしたとき、メモは巻き戻さない。
- 3の段（メモを使ったプログラムの判定：勧める時・決まりの点検・集計）は、テストの結果を見てから。

## 追記：開発利用状況の直し

- 「読み取る」の記録を、1回ずつ別の行にした。誰の欄は押した人（by）、進んだ所は「HP読み取り」、最初の言葉の欄は読んだURL。前は sid がなく、全部が「?」の1行にまとまっていた（11-11 の 12:20 の分は Claude Code の動作確認、それ以前の記録は誰の欄が「（記録なし）」）。
- 同じURLは、その日のうちなら前の結果を使う（費用0、「今日 〇時に読み取った結果を使いました」と出る）。HPを直したときは、もう一度押すと読み直す。サーバーを再起動すると、この使い回しは消える。
- 並び順：「新しい順」は始めた時刻で並べる。「最後に動いた順」を別に足した（前は最後の動きで並べていたので、12:20 に始まった行が 17:29 の位置に出ていた）。
