## 0. この書面が生まれた経緯

位置補正の相談から始まった話です。流れを短く残します。

1. ユーザーの課題：国交省の地図でのピン立ては利用者に難しい。Google Maps API は高い。Google マップの一般ページでピンを立て、URL から座標を抜く案を考えた。
2. Claude.ai の見方：URL から座標は抜ける（`!3d…!4d…` がピン、`@…` は画面の中心）。ただしスマホでは短縮URLになり座標が入らない、URLの形式は保証されない、Google を経由する導線は「Google API に抗う」方針と食い違う。主役にはしない。
3. ユーザーの捉え直し：課題は位置の精度ではなく、**「今ピンを立てた位置で回答されているのか」という利用者の不安**。さらに、いまの見立ては接する道幅を視点にしているが、それが土地評価として妥当かも疑わしい。
4. 合意した方向：不安の正体は「システムが何を見て答えたのかが見えない」こと。確認を繰り返すのではなく、**見たものを見せ、点では読めない土地の様子は客に一度にまとめて答えてもらう**。答えは確定事項として固定し、以降のAIに推測させない。
5. ユーザーの提案：ピン → 標準評価のあと、**設問・回答形式の複数選択**（形状・傾斜・車の止めやすさなど）で答えてもらい、「伝えた」という安心感を狙う。

この書面は 5 を、いまのコードの上に設計したものです。

## 2. 設計の考え方（3つ）

**① 見たものを見せる（レシート）**
システムがピンから何を読んだのか、どこからが「近くの別の土地」なのかを、地図の上で見せます。客は自分の目で「合っている」と判断できます。

**② 聞くのは一度、まとめて**
①②③の一本道をやめ、一枚の設問にします。客は自分の土地を思い浮かべながら、当てはまるものに印を付けて、一度だけ送ります。

**③ 選ばれたものは、必ず答えに出る**
安心感は、選んだ瞬間ではなく「自分の答えが返事に反映されたのが見えた瞬間」に生まれます。返事が選択に触れなければ、ただのアンケート（＝お気軽にお問い合わせくださいと同じ受け身）になります。
「わからない」も選べるようにし、選ばれたら「そこは現地で確かめる価値がある」＝店へ相談する理由に変えます。

## 3. 新しい流れ

```
⓪ 市区町村（いまどおり）
1  地図でピン ＋ 面積（いまどおり）／航空写真に切り替えられる【新】
2  データ（公開データの表）＋ 地図にレシート【新】
①  設問「この土地の様子」（一枚・まとめて送信）【①②③を置き換え】
   → AIの返事（いまの③→④の一言の位置。選んだ項目に必ず触れる）
④  から先（いまどおり。店の管理画面のボタン）
```

AI を呼ぶ回数は変わりません（いまも①②は台本、③の返事で初めてAI）。一枚にまとめた分、客の操作は3回から1回に減ります。

### 3-1. 設問の画面（一枚）

見出しの一言（台本・固定）：

> 値段より先に、この土地で何ができるかを決める条件があります。地図からは読めないので、この土地の様子を教えてください。

その下に3つの段を置き、最後に書き欄と「送信」を1つ置きます。いまの「選んでも送らず、送信で送る」の決まりに合わせます。

| 段 | 選び方 | 選択肢（初期値・客の言葉） |
|---|---|---|
| A. 道との関係 | 1つ | 道に広く面している ／ 2つの道に面している（角） ／ 細い通路の奥にある ／ わからない |
| B. 当てはまるもの | いくつでも（なしも可） | 前の道が狭い・車がすれ違えない ／ 坂や段差がある・道路より高い（低い） ／ 細長い・形がいびつ ／ 車を置きにくい ／ 隣との境目がはっきりしない |
| C. いまの使われ方 | 1つ | 住んでいる家がある ／ 空き家・古い家がある ／ 何もない（更地） ／ 駐車場・畑など |

- 送信できる条件：A と C が選ばれていること（B はなしでよい）。書き欄だけでも送れる（いまどおり、AIがどれに当たるか判断する）。
- A に「わからない」があるので、B には「わからない」を置きません。B は「当てはまるものだけ」です。
- 旗竿地の「通路が2mあるか」は、設問から外します。A で「細い通路の奥」が選ばれたときは、AIの返事の最後の問いを「通路の幅は2mありますか」にします（下の 3-3）。一枚の設問に分岐を持ち込まないためです。

### 3-2. データシートへの入り方（確定事項）

送信した時点で、答えをデータシートに「お答えより」の印付きで書きます。いまの `接道`・`形と向き`・`持ち主の意向` に、`高低差`・`車`・`境界` を足します。

| 選択 | データシート |
|---|---|
| A 道に広く面している | 接道：道に広く面している（お答えより） |
| A 2つの道に面している | 接道：角地・2つの道に面している（お答えより） |
| A 細い通路の奥 | 接道：旗竿地（お答えより）・通路の幅は未確認 ／ 形と向き：奥まっている |
| A わからない | 接道：未確認 ／ signals に「接し方：客は分からない（現地確認）」 |
| B 前の道が狭い | 接道 に「／前の道は4m未満の可能性」 |
| B 坂や段差 | 高低差：あり（お答えより） |
| B 細長い・いびつ | 形と向き：細長い・不整形（お答えより） |
| B 車を置きにくい | 車：置きにくい（お答えより） |
| B 境目がはっきりしない | 境界：未確定（お答えより） ／ signals に「境界：測量の確認」 |
| C | 持ち主の意向（いまの項目のまま） |

`aiContext()` はデータシートを毎回渡しているので、以降の④⑤も自動でこの前提に乗ります。固定の指示（`system.txt`／`system_talk.txt`）に次の一文を足してください：

> 条件に「お答えより」とある項目は、利用者が確かめて答えた事実です。推測で上書きせず、その前提で話します。

### 3-3. 設問の直後のAIの返事（いまの③→④の一言の位置）

この返事が、ユーザーの狙う「伝えたという安心感」を決めます。`aiContext(0)` に、この段だけ次の指示を足します。

```
【この返事の決まり】利用者は、土地の様子を設問で答えました。
- 選ばれた項目には、すべて触れてください。触れ方は、下の「項目ごとの事実」の範囲で、
  この土地にとって何を意味するかを短く。影響の大きいものから順に。
- 項目を並べて読み上げるのではなく、話として一続きにします（全体で200字程度まで）。
- 「わからない」や「未確認」の項目は不安材料にせず、「そこは現地で確かめる価値があります」と、
  店が見る理由として一言にします。
- 項目ごとの事実にない数字や決まりを足しません。
- 道との関係が「細い通路の奥」のときは、最後の問いを「通路の幅が2mあるか」にします。
  それ以外のときは、いまどおり次のボタンで答えられる問いで終えます。
```

あわせて「項目ごとの事実」を、選ばれた項目の分だけ渡します。AIに決まりを考えさせず、台本の事実を辞書として持たせる形です。いまの①②の台本の文は、ここへそのまま移せます。

| 項目 | AIへ渡す事実（初期値） |
|---|---|
| 道に広く面している | 建て直しの条件（幅4m以上の道に2m以上接する）は、接する長さの面では心配が少ない。残るのは前の道の幅。 |
| 2つの道に面している | 角地は使い勝手がよく、建ぺい率の緩和がある地域も多い（自治体の確認が必要）。 |
| 細い通路の奥 | 通路が2m以上あれば建て直せる。2m未満なら再建築不可として見られ、値打ちは「お隣と合わせたら何ができるか」で決まる。 |
| 前の道が狭い | 4m未満の道なら、建て直すとき敷地を道側へ下げる（セットバック）ため、使える面積が減る。前の道の幅は、建てられる床面積の上限にも効く。 |
| 坂や段差 | 造成や擁壁の費用が、売るときも建てるときも効く。古い擁壁は作り直しが必要な場合がある。 |
| 細長い・いびつ | 建てられる建物の形が限られ、値段の見え方に効く。 |
| 車を置きにくい | 駐車できるかどうかは、貸すときも売るときも買い手・借り手の判断を大きく分ける。 |
| 境目がはっきりしない | 売る・分ける・建てるのどれでも、先に境界の確認（測量）が要ることが多い。 |
| 空き家・古い家 | 解体して売るか、そのまま貸すかの分かれ目は、建て直せるかどうか。 |
| 住んでいる家 | 建て直しは先の話でも、いつか渡すときに今日の条件がそのまま値打ちになる。 |
| 更地 | この条件がそのまま、この土地で何ができるかになる。 |
| 駐車場・畑など | 今の使い方を続けるか、変えるかで、確かめる決まり（農地なら転用の手続きなど）が変わる。 |

## 4. 位置への安心（レシート）

設問だけでは「ピンの位置で答えているか」の不安は残ります。地図の側で見せます。

1. **航空写真の切り替え**：地図の右上に「写真」ボタン。地理院の全国最新写真（シームレス）タイル `https://cyberjapandata.gsi.go.jp/xyz/seamlessphoto/{z}/{x}/{y}.jpg` を重ねます。無料・キー不要で、いまの淡色地図と同じ地理院タイルなので出典表示も同じ並びで済みます。ピンを置いた直後は、そのまま写真で確かめられるのが理想です。
2. **標準地を地図に出す**：評価したら、最寄りの標準地を地図に別の色の点で出し、ピンと細い線で結びます。吹き出しは「価格・前の道などは、この地点（約○m）の公的な値です」。表で分けて書いている「この土地」と「近くの別の土地」の区別が、目で分かるようになります。前の道が二つある混乱も、ここで解けます。
3. **用途地域の境目の注記**：`zoneAt` でピンを含む区域を見つけたとき、その区域の縁までの距離も測ります（平面近似で十分）。30m以内なら表の用途地域の行に「境目の近くです。ピンの位置で用途地域が変わることがあります」と注記し、AIにも同じ一文を渡します。全員に位置の確認を求めず、**結論が位置で変わる人にだけ**求める仕組みです。
4. **Google マップの URL 貼り付けは入れない**（0. の 2 の理由）。将来、写真と住所検索でも位置が決められない声が多ければ、「最後の枠」として再検討します。

段階としては、設問（3章）を先にし、レシートは次にします。設問は流れを変えますが、レシートは表示を足すだけで、流れを変えないからです。

## 5. 管理画面との関係（いまは決めないこと）

- 設問の文言と項目は、ボタンと同じく店が変えられるのが筋です。ただ、店が足した項目には「項目ごとの事実」も店に書いてもらう必要があります。設定の負担が増えるので、いまは**初期値の固定**で動かし、管理画面への載せ方は試してから決めます。
- 業態モードで設問の項目を変えるかも、いまは決めません。設問は土地そのものの確認なので、どの業態でも共通（⓪〜②が共通、の決まりの延長）と見ています。
