## 形態3種（直した形）
- 3タイプとも、客の画面で即座に反応する（ユーザー）。後で店が答える形は、選択の多い問い合わせフォームにすぎず、どのタイプでもない。
- 2番と3番は、契約スタイルが同じ（API）。違いは中身（コンテンツ）だけ（ユーザー）。

| | AI | 誘導 | 契約 |
|---|---|---|---|
| 1 選択式 | なし（用意した文言） | ボタンの流れそのもの | 売り切り |
| 2 対話型 | あり。フリートークのAIボット | なし。問いは客の話に沿う | API（3と同じ） |
| 3 AI型 | あり | あり。問いの答えが次のボタン | API |

- 月額契約（Claude Pro／ChatGPT 等）は各社の入口でしか使えず、Webアプリからは呼べない。2・3とも API が要る。

## 2番の流れ
- 入口は地図のピン立て。その後はすべてフリートーク（ユーザー）。
- AIの最初の返事が出た所から下に「これらの情報をもとにお問い合わせ」を常設し、いつでも問い合わせへ進める（ユーザー）。

## AIのスタンス（アプリが固定、店は変えない）
- 返事は毎回 **1 短文／2 入力に対する回答／3 問いかけ**（ユーザー）。これさえ守れば、中身は友達との会話でもよい（ユーザー）。
- 一番の課題は、問いかけを型にできるか（ユーザー）。→ 問いの型（事実／状況／考え／選んでもらう）と、まだ埋まっていないデータシート項目を毎回渡し、AIに一つ選ばせる。返事は「回答・問いの型・問い」に分けて受け取り、サーバーで確かめる。
- 2と3の違いは、三つ目の問いかけがどこを向くか（2＝客の話、3＝次のボタン）。
- 客が個人情報を書いても、返事で繰り返さない。こちらから名前や連絡先を聞く問いは持たせない（聞くのは問い合わせ欄だけ）。

## データ
- 2・3は、問い合わせの有無にかかわらず、データ収集・統計の商品（ユーザー）。問い合わせがあれば、記録に連絡先が付いて店へ届く。
- 個人情報は統計に入れない。要は、文中に入る個人情報がどうなるか（ユーザー）。
- 利用者のメッセージは一言ずつでなく、会話全体を総合して判断する（ユーザー）。
- 形：原文はセッションの中だけで持つ → AIが毎回の返事のたびに「総合の判断」（伏せた形）を更新する → 判断を残し、原文は捨てる。統計には判断から取った札を入れる。位置は町丁目やメッシュに粗くする。
- 会話の終わり：問い合わせ送信／往復の上限／画面を閉じた合図／時間切れ（例 30分）を重ねる。判断を毎回更新しているので、終わりの判定は原文を捨てる時期を決めるだけ。
- 集計：意味を読む・言葉にするのはAI、数えるのはプログラム。
- 会話の前に「記録され統計に使われる、AIの会社に送られる」と客に知らせる表示が要る。最終的な線引きは、売る前に専門家に確認したい。
