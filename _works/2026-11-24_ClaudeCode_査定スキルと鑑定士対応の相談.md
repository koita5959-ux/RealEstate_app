# 査定スキルと鑑定士への対応 ― 合意と相談したいこと

2026-11-24　Claude Code（ユーザーとの仕様の相談をまとめたもの）

## 1. きっかけ

- 今の3タイプは、土地の評価（標準地×面積）までしか答えられない。「土地・建物でいくら？」には「現地調査にて」としか返せない。
- 「概算でいくら？」と聞かれたら、建物は無視できない。一方、不動産屋の営業担当は調査が主で、専門的な評価の話まではしないだろうと予想される。
- 鑑定士を含む不動産屋なら、鑑定のノウハウをチャットに組み込みたい。鑑定士の事務所そのものにも売り込みたい。
- 材料：日本不動産鑑定士協会連合会の名簿から集めた鑑定業者382件（URL確認OKが340件、メールありが223件、個人会員1人の事務所が295件）。_works/2026-11-24鑑定業者_URL統合.csv（個人名・連絡先を含むため Git には入れていない。ユーザーの手元とサーバーにある）。

## 2. 合意したこと（ユーザーと Claude Code）

1. **「査定スキル」は3タイプ共通のオプションにする。初期値はON、店がOFFにすると今の機能のまま。**
   - URLで決めるものではない。「建物込みでいくら」は、店の種類と関係なく、客の側から出てくる要望だから。
2. **業態（不動産屋／鑑定士）は、査定スキルとは別の軸にする。** URLの読み取りで初期値を決め、③の出口とAIの話し方を変える（案。中身はこれから）。
3. **ロケーション確認は1つの部品にして、3タイプで共通に使う。建物の設問もここに入れる。**
   - 候補：建物の有無と種類（木造・鉄骨・RC）、築年数、延床面積、状態（住んでいる・空き家・傷みあり）。どれも、おおよそ・不明でも答えられる形にする。
   - 今の設問の部品（docs/js/survey.js）はもともと3タイプ共通。
4. **Type1は、ロケーション確認の強化だけにする。**
   - Type1の目的は、選択で訪問者のニーズを確かめること。建物の答えも記録して問い合わせに添えるだけで、計算はしない。
   - Type1は売買・仲介を見渡す作りで、相続などは元々軽く扱っている（③に店にない業務を足さない決まり、11-17）。③に業務を足すかどうかは、実テストの様子を見て決める。
5. **査定のロジックの強化は、AI対応（Type2・3）を主戦場にする。** 建物込みの概算、その根拠と幅、相続や鑑定の出口はここで扱う。

### 検討して採らなかった案
- Type1に概算の計算（原価法の簡易版）と「何のための目安ですか」の1問を入れ、Type1を「数字で答える型」にする案（Claude Code）。Type1の役割はニーズ確認のままとした。

## 3. Claude.AI に相談したいこと

1. **建物の設問の中身**：何を、何段で聞くか。訪問者が迷わず答えられることと、査定の材料になることのつり合い。
2. **Type2・3の査定の考え方**：土地（標準地）に建物を足すときの筋道（例：構造別の建て直し単価×延床×残りの年数の割合）。出すのは1つの数字か幅か。古い建物を「価値ゼロ」「取り壊し費用がかかる」とどう扱うか。
3. **「踏み込んだ回答」と鑑定の信用の線引き**：AIの概算が「鑑定の結果」と受け取られない言い方。正式な評価との差を、問い合わせの理由にする流れ（「正式な評価が要る場面ですか？」）。
4. **鑑定士の業態での出口**：相続・遺産分割、同族間の売買、財産分与、地代・家賃の改定、裁判・調停、担保・会社の資産評価など。仲介（物件を探す・代替え地・HPの物件）を前提にした今のAIの指示から、何を外し、何を足すか。宅建の免許がない事務所に言わせてはいけないこと。
5. **鑑定士への売り込み方**：今のサンプルHP「AIボット不動産」とは別に、鑑定事務所のサンプルが要るか。

## 4. 参考（今の作り）

- Type1：①データ ②設問（ロケーション）→ ③HPの業務から選択 → ④⑤。AIなし。
- Type2・3：①土地評価データ ②設問 → 以降AI（server/system*.txt）。基本の査定（角地・道幅・旗竿などの足し引き）と代替え地の提案は入っている。
- 公開データ：地価公示・地価調査・用途地域（国土交通省 不動産情報ライブラリ）。
