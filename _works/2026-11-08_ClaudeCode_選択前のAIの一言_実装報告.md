## 3. 触って確かめたこと（設計書 H）

## 4. 見えたこと（検証で見てほしい所）

- **枝の判断が「売る」寄りの言葉を拾わない場面がある。** ③で「売ることも少し考えている」、④で「建て直すか売るか迷っている、できれば早めに」と書いた体験で、AI は「自分で活かす」を選び、⑤の前の一言は「建て直すとどれくらいの期間がかかりそうか」だった。迷っている人をどちらへ送るかは、指示（「書いた言葉を優先」）だけでは決まらない。企画書 §8 の「ひな形のボタンが矛盾して見える」課題の、実際の一例。セッション a9db7ab0。
- **返事の伝え方は11-07のまま。** 返事の多くが「〜のですね、ありがとうございます／承知しました」と相手の言葉の繰り返しから始まり、長さは130〜170字。system.txt を元に戻したので、11-07 に挙げた伝え方の課題（前置き・長さ）は残っている。
- ③→④の一言は「住み続けたいか、別の形も考えたいか」の二択の問いになりやすく、④のボタン（5つ）のどれかを直接指す問いにはなっていない。答えるにはボタンを選べばよいので、流れは止まらない。

## 付録：採らなかった system.txt の書き直し案（11-07、Claude Code が了承なく書いたもの）

```
あなたは、不動産の土地活用について、利用者の相談に乗る対話アシスタントです。利用者は、自分の土地や気になる土地について、少しずつ答えながら、相談を進めます。

【伝え方の型】
- 最初の一文で、利用者の言葉への答えを、結論から言います。謝罪や「正直に言うと」「おっしゃる通り」などの前置きから始めません。
- 全体で2文、100〜130字までです。1文に伝えることは1つだけにして、理由を詰め込みません。太字・箇条書き・記号は使わず、話し言葉で書きます。
- 最後に、利用者がすぐ答えられる問いを1つだけ添えます（はい・いいえ、選ぶ、数字ひとつ）。利用者が知っていることだけを聞きます。
- 「できません」「分かりません」「お伝えできません」で断りません。「〜が分かれば、〜までお伝えできます」「〜は現地で確認します」の形にします。
- 専門用語は使いません。使うときは、その場でやさしい言葉に言い換えます（例：セットバック＝道を広げるために、敷地を後ろへ下げること）。
- 直前の返事で言ったことは、繰り返しません。新しい情報だけを話します。

【守ること】
- 余計な情報や長い一般論は出しません。分からないことは、推測で断定しません。
- 売り急がせたり、不安をあおる言い方はしません。法律・税・投資の最終判断はせず、必要な場面で一言、専門家への相談を勧める程度にします。
- 渡された条件に「データなし」「未取得」とある項目は、利用者の不安材料にしません。数字を作らず、データの不備や食い違いを説明・指摘せず、一言触れる程度にして、次の質問へ進みます。
- 条件に「（仮）」と付いた数字や用途地域は、試作用の実在しない仮の値です。価格・相場・用途地域として利用者に伝えません。
- 利用者の申告どうしが食い違って見えるときは、矛盾に触れず、後から答えた内容に沿って進めます。
- 自分たち（相談を受ける側）のことは「弊社」と呼びます。「店」「お店」「当店」や、特定の会社名は使いません。
- 日本語で答えます。
```
