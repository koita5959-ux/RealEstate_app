# タイプ1 ― 今の作りへの当てはめ案

Claude Code より。2026-11-16。Claude.AI（Fable）の「タイプ1企画書」0章・12章と、初期設定 v0.4（82b4120）への返事。決定ではなく案です。違う所はそのまま返してください。

## 1. 照らし合わせの三つの問い（ずれ2点を直した版）
1. 通路の狭い空き家で重視を「仲介」から「総合」に変えると：④の顔ぶれが入れ替わる。どちらでも「お隣と合わせる」が先頭（通路2m未満の条件札が連れてきて、印も付く）。「解体して更地にする」は、店の重視に関わらず、土地の条件札で理由つきで薄く出る。総合で増えるのは「住み続ける・建て直す」（これも薄く）。薄く出すかは土地の側、顔ぶれは店の側。
2. 公開データのない土地で「売る」を押すと：ボタンの下は穴のない一行（subPlain「古家付きのままか、更地にしてかで、売り方が変わる」）。押した後の返事は plain（「土地の値は、近くの標準地の値に、道・形・角地かどうかの違いを足し引きして見ます」）に、店の受け（uke）と次の問い（ask）が付く。
3. 店が「④のボタンの名前を変えたい」と言ったら：④は初期設定のまま。店が変えるのは「重視する業務内容」のチェックと順番で、顔ぶれが入れ替わる。書き足すのは⑤から先。

## 2. 入れ物の形
タイプ3の `ADMIN.steps`（段の配列 → 枝 → ボタン）は使わない。二つのファイルに分ける。

| 入れ物 | 中身 | 置き場所 | 誰が変える |
|---|---|---|---|
| アプリの一式 | defaults.json そのまま（businesses・categories・tags・holes・tagFacts・options・sets・rules） | `docs/data/type1_defaults.json`（読むだけ） | アプリ（版を上げる） |
| 店の設定 | 下の形 | 今は localStorage「reType1」。売り切りで渡すときは1つのファイルに書き出す（企画書13章の2） | 店 |

店の設定の形（案）：
```json
{ "v": 1,
  "hp": "https://…", "judged": { "b1": 7, "b3": 3 },        // HPの判定の点と根拠（7-6）
  "biz": ["b1", "b4"],                                        // 重視する業務内容（順番つき）
  "edit": { "sell": { "uke": "…" } },                         // 選択肢ごとに店が直した文だけ（差分）
  "more": { "sell>手元に残る額": [ { "label": "…", "reply": "…" } ] }  // ⑤から先に＋で足した段。キーは通った道
}
```
- アプリの一式と店の差分を混ぜない。アプリが版を上げても、店が直した所だけ残る。
- 文は選択肢ごと（options の id）に持つ。木は保存しない。＋で足した段だけ「通った道（id と label を > でつないだ文字）」をキーにする。⑤の next は options の中にあるので、⑥から先だけがこの形になる。

## 3. compose の置き場所
`docs/js/type1.js` に、tryout.py の compose・fill・reply を JavaScript に移す（中身は同じ決まり）。画面で動かす理由：
- 管理画面の見本（7-4）は、チェックを変えるたびにその場で並べ直す。サーバーを通すと遅れる。
- タイプ1はAIを呼ばないので、サーバーでしかできないことがない。
- メイン画面（`1_pick_main.html`、新しく作る）と管理画面（`1_pick_admin.html`）の両方から同じ関数を呼ぶ。タイプ2・3の survey.js と同じ置き方。

足すのは `landOf(S)`：①〜③の答えと公開データの表（今の fillLand・applySurvey が作る S.sheet・S.signals）から、カテゴリー（K1〜K4）・条件札・穴の値を作る。ここが今の作りとタイプ1のつなぎ目になる。

サーバーに置くのは、HPから業務内容を判定する所（7-6）だけ。`server/shop/bizjudge.js` を足し、今の read.js・listings.js が拾っているページ名・メニュー・物件の出方から点を付ける（AIなし）。11-16 の10社のAIの読み取り結果を答え合わせに使う。

## 4. 穴の値の出どころ（v0.4 の②③を含む）
| 穴 | 今の作りでの出どころ | 取れるか |
|---|---|---|
| 目安の但し書き ①種類が違う | `/api/land` の point.mismatch（want・got） | 取れる（ffe7aa3） |
| 　②容積率が違う | 標準地の容積率 point.far（例「500(%)」）と、この土地の zone.far（例「400%」） | 取れる。数字だけ抜いて比べる |
| 　③1kmより遠い | point.d（メートル） | 取れる |
| 目安が二つ（今日の5回目） | point.alt（use・price・d・location） | 取れる。目安額の穴を「住宅地の値なら約◯万円、商業地の値なら約◯万円」にするか、穴を二つにするかは決めてほしい |
| 目安額（足し引き込み）・足し引き | 今は server/altland.js の中にしかない（きっかけ発動のときだけ） | 計算を type1.js にも置くか、/api/land が返すようにする。後者を勧める（タイプ2・3で毎回渡す件とも一本になる） |
| 駅・駅距離・学区 | /api/around | 取れる |
| 店の地区 | 店のHPの「扱う地区と物件」（shop/listings.js） | 取れる |
| 代替え地・代替え広さ | altland.js | 取れる（初回約12秒） |
