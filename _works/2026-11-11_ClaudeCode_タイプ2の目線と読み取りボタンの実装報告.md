## ユーザーの課題（11-11）

- タイプ2・3共通：AIが事業所を分かったうえで話す（会話にそれが出る）
- タイプ2：社員目線／外野目線を店が切り替えられるようにする。初期は外野目線
- タイプ2：URL指定後の「読み取る」で管理項目を自動で埋め、店が手直しする
- タイプ2：自動で作った項目の一部は直せない（店が変えたくても変えられない話の材料）。それで2つの目線の違いを分かりやすくする
- 趣旨：テストで感じた「お勧めの弱さ」をなくす

## 入れたもの

1. テストの直し（3a874d2）：面積の取り違え（AIへ渡す項目名と注意書き）、「値打ちが残る」の言い回し、「④ 1／8往復」の表示
2. `POST /api/shopread`：read.js で読み（トップ＋会社概要2＋事例1）、`shop/understand.js` で API 1回。押したときだけ走る
   - 読めないHP（JSだけ・取得失敗）は API を呼ばず「外から読み取りにくい作り」と返す
   - LANの内側・自分自身へは取りに行かない（転送も1段ずつ確かめる）
   - 費用の上限・回数の制限・停止スイッチは /api/chat と同じものを使う
3. 管理画面（2_talk_admin）：目線の切り替え（初期＝外野目線）
   - 外野目線：「1」の欄は鍵（HPより・変更できません）。「HPにないが会話に効くこと」（引き受けること・土地勘・連絡の受け方）は空白の鍵
   - 社員目線：同じ欄を書き換えられる。書き換えた欄の下に「外からはこう見えています」としてHPの読みを残す
   - 免許番号はプログラムが拾った事実として、どちらの目線でも鍵。括弧の数字から更新回数を添える
   - 「店からの一言」は別枠。外野目線では出どころ付きで伝え、HPの読みと混ぜない
4. 会話（2_talk_main・system_talk*.txt）
   - 外野目線：「店が置いたAIだが外から見た目線」に書き換え（独立した第三者を名乗らない）。出どころを必ず付ける、店を信頼できると判定しない
   - 社員目線：`system_talk_staff.txt` を新設。「弊社」、引き受けは「引き受けること」に書かれた範囲だけ
   - 締め：まだ決まっていない点を1つ名指し → 現地を見ないと決まらない理由 → 社員は「弊社が現地で確かめます」、外野は「〇〇に『〜を見てもらえますか』と聞くと、はっきりします」
   - 画面に「このAIは〇〇が設置しています（〇〇目線で話します）」

## 追記：タイプ3（70e613d）
