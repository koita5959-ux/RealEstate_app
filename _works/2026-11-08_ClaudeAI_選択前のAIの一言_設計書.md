# 選択の前の AI の一言 — 設計書（Claude Code 向け）

筆者：Claude.AI ／ 読み手：Claude Code
背景と理由は、同じ日の企画書 `2026-11-08_ClaudeAI_③から④へつなぐAIの一言と書き欄の企画書.md` にある。この書面は、**何をどこで変えるか**だけを書く。行番号はずれるので、関数名で示す。
目的は、ユーザーが触って確かめられる形にすること。迷う点は決め切らず、触った結果で判断する。

## A. ③を「ボタン＋書き欄＋送信」にする

今：`askBuilding()` が `choices([...3つ], onIntent, null, 3)` を呼ぶ。第3引数が null なので、ボタンを押すとすぐ進む。

変更：
- `choices(list, null, (t, c) => onIntent(c, t), 3)` の形にする。`choices()` は onText を渡せば、ボタンは選ぶだけになり、「送信」で `onText(t, c)` を呼ぶ（④以降と同じ動き）。ボタンを選ばず書くだけでも送れる。
- `onIntent(c, t)` に書いた言葉 `t` を受けさせる。
  - `S.sheet.持ち主の意向 = c || "（ボタンは選ばず、書いて答えた）"`
  - `t` があれば、④以降と同じく `S.sheet.事情` に足す（`esc(t)`、「 / 」区切り）。
- 書き欄の薄い文字は、C の `ADMIN.hint`（なければ今の「リクエストメッセージも送れます」）。`choices()` の placeholder を、ボタンがある行では `ADMIN.hint` にする。④以降の行も同じ。
- 巻き戻し（`rewind()` / `replay()`）は、PATH に `type` が入るので今の仕組みで戻る。③の行で書いた言葉が戻ることを確かめる。

## B. ③→④の一言を API で作る

今：`onIntent()` が3種類の決まった文 `s` を作り、`goStep(0, s)`。`goStep()` は real でないので、ボタン名を読み上げる文（`topicsOf()`）を足す。

変更：`onIntent(c, t)` の最後を次の流れにする。

```js
const userText = (c ? "選んだボタン：" + c : "") + (c && t ? "\n" : "") + (t ? "書いた言葉：" + t : "");
if (REPLAYING || AI_OFF) { /* goStep() の同じ分岐にならい、RESTORE.replies を1件使う。なければ台本 s */ }
else askAI(0, false, userText, { q:3, press:c || "", typed:!!t, branch:"", place:PLACE, near:S.near.name, road:S.sheet.接道 || "", intent:S.sheet.持ち主の意向 || "", kind:"答える" })
  .then(r => goStep(0, r ? r : s + AI_FAIL, !!r));
```

- `askAI(0, …)` の `n=0` は「次は④」という意味になる。`aiContext(0)` の中の `nextButtons(0)` が④のボタンを返すので、「返事の最後の一文は、このボタンのどれかで答えられる問いに」という今の指示がそのまま効く。
- `askAI()` が `AI_HIST` に user と assistant を積むので、③→④の一言が会話の最初の発言になる。④以降の往復はこれを踏まえる。
- 失敗したときは、今の台本の文 `s` に `AI_FAIL` を付けて `goStep(0, …, false)`。今と同じ見え方に戻る。
- `inquiryBar()` は今どおり④から出す（`onIntent()` 内の呼び出しはそのまま）。
- 設計メモ：real のときは `goStep()` が「渡したもの：一つ前の答えへのAIの返事」を出すので、そのままでよい。
- 往復の数：`LIMIT` は「④を1往復目と数える」。③の往復は**数に入れない**（`askAI()` の中で数えていないので、今のままでよい）。費用は1セッション1往復増える。

## C. 業態モードに「受け方」と「書き欄の例」を足す

### admin_mode.html

`MODES` の各モードに2つ足す。

```js
m1: { …, stance:"お客さんの答えを、買い手がまず見る点として受け止める。",
         hint:"ほかに気になることがあれば一言どうぞ（例：急ぎではない）" },
m2: { …, stance:"お客さんの答えを、この土地に何が建つかの条件として受け止める。",
         hint:"ほかに気になることがあれば一言どうぞ（例：お隣も空いている）" },
m3: { …, stance:"お客さんの答えを、選べる活かし方の幅として受け止め、一つを勧める前に並べて比べる。",
         hint:"ほかに気になることがあれば一言どうぞ（例：売ることも少し考えている）" },
m4: { …, stance:"お客さんの答えを、この土地を誰がどう持つかの話として受け止める。",
         hint:"ほかに気になることがあれば一言どうぞ（例：兄弟で持っている）" },
m5: { …, stance:"", hint:"" },
```

- `loadMode(k)`：`stance = m.stance; hint = m.hint;` を持つ（`closeText` と同じ扱いの変数）。
- 設定画面：業態モードの下に、「受け方」（1行）と「書き欄の例」（1行）の入力欄を出す。店が書き換えられる。空でもよい。
- `commit()`：保存に足す。`{ mode:modeKey, name:MODES[modeKey].name, stance, hint, steps, close:closeText, limit }`
- `loadSaved()`：古い保存（stance がない）は `MODES[sv.mode].stance` / `.hint` で補う。
- 説明欄（`renderHelp()`）に、受け方は「選択の前の AI の一言が、お客さんの答えをどう受け止めるか」だと一言足す。

### index.html

- `ADMIN_DEFAULT` に m3 の `name`・`stance`・`hint` を足す（上と同じ文）。
- `ADMIN` の読み込みは今のまま。`ADMIN.name` / `ADMIN.stance` / `ADMIN.hint` がなければ空として扱う。

## D. AI に渡す状況を足す（`aiContext(n, ask)`）

今の中身（条件の一覧、データなしの注意、相談の方向、聞く段階の指示、次のボタンの指示）は残し、**条件の一覧の後**に次を足す。

```js
if (ADMIN.name) c += "\n弊社の業態：" + ADMIN.name;
if (ADMIN.stance && ADMIN.stance.trim()) c += "\n弊社の受け方：" + ADMIN.stance.trim();
const axis = n === 0 ? (ADMIN.steps[0] && ADMIN.steps[0].topic) : n === 1 ? (BRANCH && BRANCH.name) : (ADMIN.steps[n] && ADMIN.steps[n].topic);
if (axis && n < LIMIT) c += "\n次に聞くこと：" + axis;
```

次のボタンがある場合の指示は、次の文に置き換える。

```
次に利用者へ出るボタン：（ボタン一覧）
返事は、ここまでの答えを弊社の受け方で受け止めて、この土地・この相談の見立てを一言で返してから、このボタンのどれかで答えられる問いで終えてください。ボタンの名前を並べて読み上げないでください。
```

- 受け方が空（「一から自分で作る店」）なら、業態と受け方の行は出さない。今の会話のまま動く。
- context は server.js で 2000字に切られる。11-07 の記録では 700〜900字なので収まるが、E で枝の候補を足すと増えるので、送る前に長さを確かめる。

## E. ④で書いた言葉があるとき、枝を AI に決めさせる

今：`goStep()` の `enter(c || t)` で、ボタンの位置から枝を決める。書いた言葉だけのときは `j = -1` で、枝1に固定（ダミー）。

変更の考え方：**⑤のボタンは枝で決まるので、枝の判断と④→⑤の一言は同じ往復で作る。**

- ボタンだけで、書いた言葉がない：今どおりボタンの枝。
- 書いた言葉がある（ボタンの有無を問わない）：BRANCH を決めずに AI を呼ぶ。
  - `aiContext(1)` で、BRANCH が未定なら、ボタンの指示の代わりに次を渡す。

```
次に利用者へ出るボタンは、相談の方向で変わります。
方向1「（枝1の name）」：（枝1のボタン）
方向2「（枝2の name）」：（枝2のボタン）
（ボタンを選んでいれば）ボタンからは方向Nにあたります。
利用者の書いた言葉を優先して、合う方向を一つ選び、その方向のボタンのどれかで答えられる問いで終えてください。
返事の最後に、行を分けて【方向1】か【方向2】とだけ書いてください。
```

  - 返事を受けたら、最後の `【方向([12])】` を読み取って `BRANCH = ADMIN.steps[1].branches[N-1]` にし、その行を消してから表示と `AI_HIST` に入れる。読み取れなければ、ボタンの枝（ボタンもなければ枝1）。
  - `S.sheet.相談目的` は今どおり（ボタン、なければ書いた言葉）。
- 再表示（RESTORE）：記録の reply には【方向N】が残る。戻すときも同じ読み取りと消し込みをする。再表示の処理で④のボタンから枝を決めている所（`p4` から BRANCH を作る所）は、reply に【方向N】があればそちらを優先する。

## F. 話し方の決まりを足す（server/system.txt）

- 1行目の「利用者は、岐阜市などの自分の土地や気になる土地について」を「利用者は、自分の土地や気になる土地について」にする。
- 次の2行を足す。

```
- 利用者がボタンを選び、同時に言葉も書いたときは、書いた言葉を優先して受け止めます。ボタンと食い違って見えても、矛盾を指摘しません。
- 利用者が答えの代わりに質問を書いたときは、先に短く答えてから、次の問いへ戻ります。
```

- system.txt の書き直し案（未確定・GitHub に上げていないもの）がある場合は、それと突き合わせて、この2行と地域の決め打ちの削除だけを先に入れる。

## G. 記録

- `askAI()` に渡す meta に `branchBy`（"button" / "ai" / ""）を足す。server.js `parseBody()` の meta の許可リストに `"branchBy"` を足す。
- 「ボタンを選ばずに書いた」は、meta の `press` が空で `typed` が true で分かる。開発の利用状況で、この往復に印が見えるとよい（表示の形は任せる）。

## H. 触って確かめる手順

すべて `?by=test` を付けて開く（記録を見分けるため）。設定画面で「総合系」を確定してから始める。

1. **今回の事例の再試行**：東京都・中央区、茅場町あたりにピン、120㎡、①道に広く面している、②すれ違えない、③住んでいる家がある（書かずに送信）。
   - 見ること：③→④の一言が台本の文でなく、「住まい」「前の道」を受け止めた見立てになっているか。④のボタンで答えられる問いで終わっているか。ボタン名の読み上げがないか。
2. **③で本音を書く**：1と同じ道で、③で「住んでいる家がある」を選び、「売ることも少し考えている」と書いて送信。
   - 見ること：③→④の一言が売却に触れ、④の「売る」へ自然につながるか。
3. **④で書くだけ**：④でボタンを選ばず「建て直すか売るか迷っている」と書いて送信。
   - 見ること：枝が AI で決まり、⑤のボタンとその前の一言がかみ合うか。開発の利用状況で branchBy が ai になっているか。
4. **④でボタンと食い違う言葉**：④で「住む・建て直す」を選び、「でも早く売りたい」と書いて送信。
   - 見ること：枝が「手放す」になるか。⑤のボタンが矛盾して見えないか（企画書の課題。見え方を記録する）。
5. **業態を変える**：設定画面で「相続や税の相談から始める店」を確定し、1と同じ道で③まで進める。
   - 見ること：同じ事実への③→④の一言が、総合系と変わるか。
6. **一から自分で作る店**：受け方が空のとき、今の会話と同じように崩れず動くか。
7. **再表示**：上のどれかを開発の利用状況から再表示し、③の書いた言葉、③→④の一言、枝、⑤のボタンまで戻るか。
8. **AI を止めた場合**：`?ai=off` で開き、③→④が今の台本の文で出るか。
