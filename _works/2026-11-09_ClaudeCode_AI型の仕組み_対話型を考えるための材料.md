## 1. AI型の流れ（いま公開中のもの）

公開画面：https://taskboard.asuscomm.com/RealEstate_app/docs/proto/

| 段 | 中身 | 誰が返すか |
|---|---|---|
| ⓪ | 都道府県・市区町村 → 地図 → ピン（面積は任意） | 画面だけ |
| データ | ピンの位置で国の公開データを取る（地価公示・用途地域。いまは見本の値、キー待ち） | サーバー |
| ① | 道への接し方（広く面している／旗竿地／わからない） | **台本**（固定の文） |
| ② | 前の道の幅 4m、または旗竿の通路 2m | 台本 |
| ③ | 建物の有無 | 台本で問い、③→④の一言は **AI** |
| ④ | 相談の目的（店が管理画面で書いたボタン） | AI |
| ⑤ | ④で選んだボタンから2つの枝に分かれ、枝ごとのボタンが出る | AI |
| ⑥〜 | 店のボタンがなければ書き欄だけ | AI |
| 終わり | 往復の上限（ボタンを設定した段の数＋2）で「AIはここまでです…」 | 画面 |

- どの段も「ボタンを選ぶ＋書き欄＋送信」です。ボタンだけ、書いた言葉だけ、両方、のどれでも進めます。
- 問い合わせボタンは④から下にずっと出ていて、いつでも問い合わせへ進めます。
- ①②を台本にしているのは、「根拠のある決まりを一つ渡し、地図では読めない一点を正直に聞く」という一投目の型を守るためです（11-04 合意）。

## 2. 1回の往復でAIに渡しているもの

AIを呼ぶのはサーバー（`server/server.js` の /api/chat、モデル claude-opus-5-5）です。1回の呼び出しで渡すのは次の3つです。

1. **固定の指示**（`server/system.txt`、全業態で共通）：短く（150字・3文まで）、記号は使わない、答えてから問いを一つ添える、あおらない、データなしを不安材料にしない、矛盾は指摘しない、書いた言葉をボタンより優先する、など。
2. **画面から渡す状況**（index.html の `aiContext()` が毎回作る）：
   - データシート：ここまでの答えと公開データ（接道・持ち主の意向・事情・用途地域など、表は19行）
   - 公開データの扱いの注意（見本の値は伝えない／標準地の値はこの土地の値段ではない）
   - 弊社の業態と**受け方**（店が管理画面で書く一文）
   - **次に聞くこと**（その段の題）と、**次に出るボタンの一覧**。指示は「受け止めて見立てを一言返し、このボタンのどれかで答えられる問いで終える。ボタン名は読み上げない」
   - ④で言葉を書いたときは、2つの枝のボタンを両方見せて「合う方向を選び、最後に【方向1】か【方向2】と書く」と頼む（画面がそれを読んで枝を決め、表示からは消す）
   - 上限に着いたときは「問いかけなし・2〜3文で終える」
3. **会話の履歴**（直近20件。利用者の発言は「選んだボタン：…／書いた言葉：…」の形）

要するに、**AI型の誘導は「次のボタン一覧を毎回AIに見せ、最後の問いをそこへ向けさせる」ことで成り立っています。** 流れ（何段あるか、どこで分かれるか）は画面のプログラムと店の設定が握っていて、AIは一言と問いを作るだけです。

## 3. AI型の周りにある、共通に使える仕組み

対話型でも、そのまま使えるはずのものです。

- サーバー：APIキーを隠す、1分12回/人、入力の長さ制限、同時に処理するAIの数と順番待ち、1日の費用上限、停止スイッチ
- 入口の人数制限（同時10人・1日50件。いまは一時停止中）
- 記録：セッションごとの状態とスナップショット、画面の動き、往復ごとのトークン・費用
- 再表示（元に戻す）、利用状況・開発利用状況の画面、「送信と原文」の欄（AIに送った全文と原文を見せる）
- 公開データの取得（ピン → 地価・用途地域）
- 管理画面（店が業態・受け方・各段のボタン・往復の上限を書く）

## 4. 対話型との違いが出る所

11-04 の合意では、2と3の違いは**最後の問いがどこを向くか**です（2＝利用者の話、3＝次のボタン）。上の構造に当てはめると、違いは次の所に集まります。

- **次のボタン一覧を渡さない**と、AIの問いは利用者の話に沿う。AI型の作りから、ここを外すだけで対話型の骨組みに近づく。
- 一方で、**何を聞けばよいかの手がかりもなくなる**。11-04 の案は「問いの型（事実／状況／考え／選んでもらう）と、まだ埋まっていないデータシートの項目を毎回渡し、AIに一つ選ばせる」。AI型の「次に聞くこと」の位置に、これが入ることになる。
- **データシートの埋まり方**：AI型ではボタンの答えで埋まる。対話型ではAIが会話から読み取って埋める必要がある（11-04 の「総合の判断を毎回更新して残す」と同じ話）。
- **①②の台本**：対話型は「ピンの後はすべてフリートーク」（ユーザー、11-04）。接道の一投目をAIに任せるのか、最初の一言だけ台本で残すのかは未定。
- **終わり方**：AI型は往復の上限で打ち切る。対話型も上限は持つ（11-04）。
- **店が書けるもの**：AI型ではボタンと枝。対話型では、ボタンがない分、受け方と「聞きたい項目」くらいしか残らない。

## 5. AI型で見えている課題（対話型にも響くもの）

- AIの伝え方：返事30件を分けると、専門用語の説明がない、「できません」で断る、謝罪や前置きから入る、長い、問いが答えにくい、同じことを繰り返す（handoff の記録より）。対話型は誘導のレールがない分、ここがそのまま品質になる。
- 返事を点検して作り直す仕組み（なし／決まりで点検して外れたら1回作り直す／毎回見直させる）は、商品タイプの差として持つことに合意済み（11-08）。対話型にどの段を当てるかも、相談の材料になる。

1. 対話型の「問いの向け先」を、AI型の「次のボタン一覧」に代わる何で持つか（問いの型＋空いている項目、の案を含めて）。
2. 対話型で、店が管理画面に書くものは何か。
